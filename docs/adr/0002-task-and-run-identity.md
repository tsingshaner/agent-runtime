# Task 与 Run 一一对应并使用独立身份

A2A Task 表示待完成的工作，Run 表示一次执行尝试；首版一个 Task 对应一个 Run，两者使用独立标识。审批和补充输入都继续原 Task 与 Run，Run 进入终态时 Task 同时结束；后续工作创建新的 Task 和 Run，仍可属于同一会话。

此前考虑过一个 Task 关联多个 Run，但首版没有需要这种关系的实际流程，因此不增加跨 Run 任务编排。独立标识保留协议身份与执行身份的区别，不因一一对应而将两者当作接口别名。

等待补充输入时，Run 保持活动并进入 waiting_input，继续占用会话；可以查询、回答或取消，但不接纳该会话的新运行。断开订阅不取消执行，宿主重启后仍将遗留运行标记为 interrupted；A2A 将等待输入映射为 input-required，终态 Task 不允许重新打开。

重启后旧审批与输入请求全部失效；原生 checkpoint 存在不代表可安全继续，适配器只有在能确认不会继续旧操作时，才允许原会话开始新运行。无法确认时保留现场、明确拒绝续接，由用户选择新建会话，而不是隐式恢复待执行工具；这接受部分中断会话无法原地恢复的限制，以避免重放副作用。
