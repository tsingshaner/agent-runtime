# 在共享进程空闲时应用需要重启的资源更新

每轮执行开始时固定资源配置；配置变更若需要重启共享 runtime 进程，必须等待该进程所有活动运行结束，并明确标记为待生效。首版接受配置生效延迟，以保留共享进程模型并避免打断其他会话，不为资源更新新增进程池。

Codex 默认以项目为进程共享边界，同项目会话共用进程，不跨项目共享；只加载项目显式启用的技能与 MCP，不自动继承用户全局资源。资源隔离须通过真实验证，不能仅凭原生接口提供目录或配置参数就视为成立。

进入待生效状态后，暂停该进程接纳新运行，让已有运行结束后再重建；新请求明确返回资源更新中的错误，不隐式排队，避免持续的新运行饿死配置更新。

等待期间仍允许查询、回答输入请求、响应审批和取消已有运行，避免暂停接纳变成无法解除的等待。

显式绑定且启用的 skill、knowledge 或 MCP 在准备阶段失败，会阻止本轮模型执行并指出故障资源，避免模型在缺失用户指定能力时继续执行。用户修复或禁用后可重试；Memory 故障按独立的降级策略处理。

运行中普通工具失败作为明确的工具错误交给模型处理；进程退出、协议损坏或状态存储失败等导致执行不能可靠继续的故障才结束运行。失败不能伪装为空结果或成功；存储失效时仍遵守既有契约，不伪造无法持久化的终态。

每轮固定绑定、启停与连接配置，不为全部资源文件制作运行快照；按需读取获得当时完整的文件，已经注入上下文的内容不追溯替换。这样保留原子写入保障，同时避免为首版引入文档版本仓库。
